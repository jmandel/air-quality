KEY CLARIFICATIONS INCORPORATED
────────────────────────────────

✅ UNITS STORAGE
   • Human-readable TEXT stored in sensors.unit column
   • Examples: "ppm", "°C", "µg/m³"
   • NOT a separate unit_id or units table
   • NOT extracted from state field
   • Stored ONCE per sensor (canonical form)
   • Rationale: Simple, clean, rarely changes

✅ AGGREGATION APPROACH
   • Aggregate ALL data from day 1 onwards
   • NOT just data older than 7 days
   • Real-time buffer with 60-second flush
   • Minutely summaries stored forever
   • Raw data auto-deleted after 7 days

✅ NO unit_id COLUMN
   • User specifically requested NO unit_id
   • Use direct TEXT column instead
   • Keeps schema simple and maintainable

FINAL SCHEMA DESIGN
───────────────────

sensors (static reference table)
┌─────────────┬──────────┬─────────────────────────────────────────┐
│ id          │ INTEGER  │ 1-byte reference (PRIMARY KEY)          │
│ name        │ TEXT     │ SSE id field ("sensor-co2")            │
│ display_name│ TEXT     │ SSE name field ("CO₂")                 │
│ unit        │ TEXT     │ Canonical unit ("ppm", "°C", "µg/m³")  │
└─────────────┴──────────┴─────────────────────────────────────────┘

readings (raw data, 7-day retention)
┌─────────────┬──────────┬─────────────────────────────────────────┐
│ ts          │ INTEGER  │ Timestamp in milliseconds               │
│ sensor_id   │ INTEGER  │ Foreign key → sensors.id                │
│ value       │ REAL     │ Numeric sensor value                    │
└─────────────┴──────────┴─────────────────────────────────────────┘

readings_aggregated (minutely summaries, permanent)
┌─────────────┬──────────┬─────────────────────────────────────────┐
│ minute_ts   │ INTEGER  │ Timestamp rounded to minute             │
│ sensor_id   │ INTEGER  │ Foreign key → sensors.id                │
│ avg_value   │ REAL     │ Average value for the minute            │
│ min_value   │ REAL     │ Minimum value for the minute            │
│ max_value   │ REAL     │ Maximum value for the minute            │
│ sample_count│ INTEGER  │ Number of samples in minute             │
└─────────────┴──────────┴─────────────────────────────────────────┘

═══════════════════════════════════════════════════════════════════════════════

DATA FLOW
─────────

  SSE Event arrives
       ↓
  1. Store in readings (raw table)
       ↓
  2. Add to aggregation buffer
       ↓
  3. Every 60 seconds: Flush completed minutes to readings_aggregated
       ↓
  4. After 7 days: Delete from readings (raw)
       ↓
  readings_aggregated remains forever (or 1+ years)

═══════════════════════════════════════════════════════════════════════════════

QUERY STRATEGY
──────────────

  Recent data (<7 days):
  • Use readings table
  • Full resolution (every ~10 seconds)
  • High detail for analysis

  Historical data (>7 days):
  • Use readings_aggregated table
  • Minutely summaries
  • 60× smaller storage

  API automatically routes to correct table based on timestamp range!
